# 悬浮窗设计

## 概述

悬浮窗是 TokenStats 的核心交互入口，提供一个始终置顶的 320×140 像素紧凑面板，让用户无需切换窗口即可实时了解 token 消耗状态。

## 窗口配置

```json
// tauri.conf.json
{
  "label": "floating",
  "url": "floating.html",
  "width": 320,
  "height": 140,
  "x": 40,
  "y": 80,
  "decorations": false,
  "alwaysOnTop": true,
  "transparent": true,
  "skipTaskbar": true
}
```

| 属性 | 值 | 说明 |
|------|-----|------|
| decorations | false | 无标题栏，自绘 UI |
| alwaysOnTop | true | 始终置顶，不被其他窗口遮挡 |
| transparent | true | 背景透明，实现半透明效果 |
| skipTaskbar | true | 不在任务栏显示 |

```
┌──────────────────────────────────────────┐
│  ┌─────────┐  ┌──────────┐  ┌────────┐ │
│  │  ★ 今日  │  │  5分钟   │  │  累计  │ │

│  ════════════ 透明度滑块 ════════════   │
└──────────────────────────────────────────┘
```

### 三卡片区域

| 卡片 | 内容 | 交互 |
|------|------|------|
| **英雄卡片（今日）** | 今日 token 总量 + 星标图标 | 点击打开主窗口 |
| **5 分钟卡片** | 近 5 分钟 token + sparkline 迷你折线图 | 实时动态更新 |
| **累计卡片** | 累计 token 总量 | 静态展示 |

### 底部信息栏

- **左侧**：当前模型名 + 彩色圆点（颜色由 `colorForModel()` 哈希计算，每个模型固定颜色）
- **右侧**：连接状态指示器（紫色=已连接，玫红色=断开）

### 透明度滑块

底部滑块控制窗口透明度，映射到 `AppSettings.opacity`（0.0-1.0）。

## Sparkline 图表

悬浮窗的 sparkline 是一个 Canvas 绘制的迷你折线图，展示近 5 分钟的 token 使用趋势。

### 渲染流程

```
1. 获取最近 N 个小时统计数据
2. 映射到 Canvas 坐标系（宽度=卡片宽度，高度=40px）
3. 绘制三次贝塞尔曲线（平滑连接数据点）
4. 填充渐变区域（从线条颜色到透明）
5. 动画：从左到右逐步绘制（300ms）
```

### 视觉效果

- 线条：2px 宽度，颜色随主题变化
- 填充：线性渐变，从线条颜色（20% 透明度）到完全透明
- 动画：`requestAnimationFrame` 驱动的绘制进度动画
- 无数据时：显示空状态占位符

## 智能轮询

悬浮窗使用 `createSmartPolling()` 实现自适应轮询频率：

### 状态机

```
ACTIVE (3s 间隔)
  │
  ├── 数据有变化 → 保持 ACTIVE
  │
  └── 连续 3 次无变化 → IDLE
  
IDLE (30s 间隔)
  │
  ├── 数据有变化 → 回到 ACTIVE
  │
  └── 页面隐藏 → PAUSED
  
PAUSED (停止轮询)
  │
  └── 页面可见 → 立即 fetch → ACTIVE
```

### 轮询实现

```typescript
function createSmartPolling(
  fetchFn: () => Promise<void>,
  options: {
    fastInterval?: number;   // 默认 3000ms
    slowInterval?: number;   // 默认 30000ms
    noChangeThreshold?: number;  // 默认 3 次
  }
): { start, stop, reset }
```

- `start()`：启动轮询，监听 visibility change 事件
- `stop()`：停止轮询，移除事件监听
- `reset()`：重置到 fast 模式

### 优势

- **活跃时 3s 刷新**：用户正在看数据时保持实时性
- **闲置时 30s 刷新**：无人关注时减少 90% 请求
- **页面隐藏时暂停**：避免后台资源浪费
- **恢复时立即刷新**：切回悬浮窗时第一时间获取最新数据

## 告警系统

### 5 分钟阈值告警

当 5 分钟内 token 消耗超过 `alert_threshold_5m`（默认 20,000）时触发：

1. 发送系统桌面通知（如已启用）
2. 悬浮窗显示告警状态
3. 告警冷却时间 5 分钟，避免频繁通知

### 告警流程

```
每次轮询获取 stats
  │
  ├── five_min_tokens < threshold → 正常状态
  │
  └── five_min_tokens >= threshold
        │
        ├── 距上次告警 > 5 分钟 → 发送通知 + 记录告警时间
        │
        └── 距上次告警 ≤ 5 分钟 → 静默（冷却中）
```

## 交互操作

### 鼠标交互

| 操作 | 行为 |
|------|------|
| 单击英雄卡片 | 打开主窗口 Overview 标签 |
| 双击窗口 | 最大化/还原悬浮窗 |
| 右键点击 | 弹出上下文菜单 |
| 拖拽标题区域 | 移动窗口位置 |

```

│  统计             │

└──────────────────┘
```

### 键盘快捷键

| 快捷键 | 功能 |
|--------|------|
| `Ctrl+Shift+H` | 切换悬浮窗显隐 |
| `Ctrl+,` | 打开主窗口设置标签 |

## 窗口状态持久化

以下状态持久化到 localStorage：

| 状态 | key | 说明 |
|------|-----|------|
| 窗口位置 | `floating_x`, `floating_y` | 每 2 秒保存一次 |
| 透明度 | 继承 `AppSettings.opacity` | 通过 save_settings 持久化 |
| 最大化状态 | 内存中 | 重启后恢复为普通大小 |

## 动画与视觉反馈

### 徽章动画

- **"LIVE" 徽章**：脉冲动画，标识数据正在实时更新
- **"NEW" 徽章**：闪光动画，新事件到达时短暂显示

### 卡片动画

- 数据更新时：数字渐变过渡
- 新事件到达：卡片短暂高亮

### 连接状态指示

| 状态 | 颜色 | 说明 |
|------|------|------|
| 已连接 | 紫色 (violet) | 后端正常运行 |
| 断开 | 玫红色 (rose) | 后端连接失败 |

状态检测：前端轮询成功 → 已连接；连续失败 → 断开。

## 与主窗口的协作

### 数据共享

悬浮窗和主窗口共享同一个 `AppState`，通过各自的 Tauri Command 调用访问相同数据。

### 交互联动

```
悬浮窗点击 → show_main_window("overview")
主窗口设置变更 → save_settings → 悬浮窗下次轮询读取新设置
悬浮窗隐藏 → Ctrl+Shift+H → 显示
主窗口托盘 → Toggle Floating → 切换悬浮窗
```

### 生命周期

1. 应用启动 → 根据 `show_on_start` 决定是否显示悬浮窗
2. 用户通过托盘菜单或快捷键切换显隐
3. 应用退出 → 悬浮窗随应用关闭
